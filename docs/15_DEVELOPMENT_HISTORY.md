## 현재 제공 방식

- 공개 화면은 ORS 공개 확인분만 기본값으로 제공한다. 진행 중 신청·보완기한·승인율·심사기간은 공개자료 미확보로 표시한다. 표준 원장과 제출기한 기능은 별도 합성 예시다.
- 내부 관리 Tool과 다운로드한 ORS 자료는 로컬 Excel·JSON·독립 HTML로 검토한다. 각 원본의 시트·행·셀·수식과 출처를 추적한다. 다운로드 ORS의 파일 자체가 관리 Excel의 독립 시트로 모두 옮겨진 것은 아니다.
- Excel과 웹은 검증된 파일 단위로 자료를 교환한다. Excel 편집이 열린 웹에 실시간 동기화되거나 웹 선택 조건을 Excel에 저장하지 않는다.
- 시각 기준은 [디자인 명세](../design.md)를, 도구별 실제 사용과 미사용은 [도구 점검](14_DASHBOARD_TOOLING_REVIEW.md)을 따른다.

## 남은 개선 과제

1. 근거가 없는 계산과 신규·개정 불일치의 담당자 확인. `기준 미확인`을 숫자 0으로 치환하거나 보류를 임의 해제하지 않는다.
2. 새 Excel 검증 현황 시트와 추가 행 범위를 별도 사본에서 다시 검토. 현재 구현되지 않은 Excel 시트나 전체 업무 수식 복원을 완료로 표시하지 않는다.
3. 최근 로컬 웹 변경의 실제 브라우저 조작·모바일 화면·키보드 동작 검증. 서버 렌더링과 빌드만으로 사용자 조작을 검증했다고 하지 않는다.
4. 실제 운영 DB가 필요해지면 Supabase 테스트 프로젝트에서 SQL 적용, 인증, RLS·조직 격리·감사로그를 먼저 검증. 현재는 초안뿐이다.
5. 외부 자동 알림, 상시 감시, ORS 사이트 직접 수집은 미구현. 공개자료의 이용조건과 내부 승인·권한을 확인한 뒤 별도 개발한다.

## 공개 배포 검사 원칙

`web/dist`와 저장소 루트의 Pages 산출물에는 공개 허용목록의 코드·공개 Excel·설명서만 둔다. 로컬 `inputs/`, `outputs/`, `local/`, 내부 JSON/HTML, 원장·연락처·검토 메모, 비밀키는 배포하지 않는다. Python·웹 테스트, Python/JavaScript 집계 동등성, React 빌드, 정적 파일 허용목록 및 원격 CI/Pages 상태를 확인한다. 실제 브라우저 조작과 모바일 화면 검증은 HTTP 응답 및 빌드 성공과 구분한다.
