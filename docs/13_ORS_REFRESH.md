# ORS 파일 → Excel → 로컬 대시보드 갱신

다운로드한 ORS Excel/ZIP을 읽어 기존 관리 파일의 ORS 시트와 조회 수식을 갱신하고, 같은 저장 결과에서 JSON·웹 화면을 생성한다. ORS 사이트 직접 접속이나 상시 감시는 구현하지 않았다.

## 처리 순서

1. 입력·기준 Excel·설정·프로그램 판본과 기존 결과의 해시를 확인한다. 같은 입력으로 완료된 결과가 온전하면 새 폴더와 파일을 만들지 않고 기존 결과를 연다. 변경이 있으면 원본과 기존 결과를 보존하고 별도 실행 폴더를 만든다.
2. 파일명의 실제 자료 날짜, 열 제목, 복합 신청 식별값을 확인한다. 번호만 같거나 제목만 비슷한 자료는 합치지 않는다.
3. 같은 신청이 한 번씩 연결된 경우 상태·처리일·이력을 가져온다. 기존 수식은 덮어쓰지 않는다.
4. Excel에서 연결된 조회 시트와 분류 시트를 부분 재계산한다. 담당자·내부 단계·메모는 직접 입력한 값을 유지한다.
5. 새 수식 오류·허용 범위 밖 값 변경·Excel/JSON 분류 차이가 있으면 최신 결과로 지정하지 않는다.
6. 검증한 엑셀 두 개와 같은 데이터의 JSON·독립 HTML을 저장하고 최근 결과 링크를 갱신한다.

## 자동 반영과 보류

| 항목 | 처리 |
|---|---|
| 고유하게 연결된 상태·처리일·이력 | 원본 ORS 시트 갱신 후 기존 조회 수식 계산 |
| 담당자·검토 메모·내부 단계 | 기존 수동 입력 유지 |
| 감축량·금액·기본정보 변경 | 변경 후보로 보류 |
| 신규·미연결 신청 | 보류 목록 표시, 업무 원장에 자동 추가하지 않음 |
| 중복 식별값·동일 날짜의 상충 자료 | 자동 확정하지 않음 |
| 이전 자료·과거 처리일 | 최신값을 덮어쓰지 않음 |
| 공란 | 기존값을 삭제하거나 0으로 바꾸지 않음 |
| 자료 날짜 미확인·열 구조 변경 | 날짜 또는 매핑 확인 필요 |

**기존 관리표의 수식 연결된 열이 자동 반영 대상이다.** 수동으로 복사해 둔 값은 자동 연결로 바꾸지 않는다. 최신 ORS 값은 자료 목록의 ORS 원본 시트에서 함께 확인한다. 수동 상태와 ORS 상태가 다른 경우 담당자가 검토한다. 새 분류는 기존 Excel의 ‘그 외·새 분류’에 포함되며 웹에서는 개별 분류로 조회한다.

## 로컬 실행

Windows용 `scripts/refresh_ors.py --config <로컬 설정.json> --apply`를 실행한다. `--apply`를 생략하면 변경 계획만 작성한다. 사용자에게 제공한 실행 파일은 이 명령을 실행하는 바로가기다.

`refresh-ledger.json`은 같은 자료·설정·프로그램 판본으로 검증 완료된 결과와 결과 파일의 해시를 기록한다. 입력 파일이 같고 결과가 모두 온전하면 반복 실행을 건너뛴다. 새 ORS 파일, 기준 Excel 수정, 설정·프로그램 변경, 결과 누락·변조 또는 미래 날짜 자료의 사용 가능일 도래는 다시 검증해야 한다. 날짜 판정은 한국시간 기준이다. 실패한 같은 입력은 무한 재시도하지 않는다. 오류 원인과 외부 상태를 확인한 경우에만 `--retry-reviewed --apply`로 한 번 다시 실행한다.

기존 검증 완료 결과에 장부가 아직 없다면 `--register-current`로 원본 해시, 자료 목록, JSON 계약, HTML 내장 자료, 웹 빌드, 기존 검사 기록을 확인한 뒤 등록한다. 이 명령은 Excel 계산과 결과 재생성을 하지 않는다. 검증 근거가 부족하면 등록하지 않는다.

설정에는 기준 Excel 두 개, 소스 ID, 기준 날짜, 이전 로컬 검토 JSON, 입력 폴더/ZIP, 결과 폴더, Python/Node/PowerShell 경로를 지정한다. 사내 경로·원장은 공개 저장소에 저장하지 않는다. 최초 기준 날짜는 자료 근거를 확인해 지정한다. 단순 파일 수정 시각을 공식 자료 날짜로 사용하지 않는다.

필요 조건: Windows 데스크톱 Excel, PowerShell 7, `requirements-ingest.txt`의 Python 라이브러리, Node, 빌드된 `web/dist`. 두 번째 실행부터는 마지막 검증 완료 사본을 기준으로 한다. 갱신 실행 중 다른 갱신 실행은 차단한다. 계산·스키마·집계 검증에 실패하면 기존 최근 결과를 유지한다.

다운로드 날짜가 파일명에 `YYYYMMDD` 또는 `YYYYMMDDhhmmss`로 있어야 한다. 날짜를 임의로 최신으로 바꾸지 않는다. 날짜 없는 파일은 보류된다. Excel에서 작업 중이면 먼저 저장한다. 관리 시트 열 이동·삭제, 추가 행의 연결 범위 초과는 별도 매핑 검토가 필요하다.

## 결과와 범위

- `최근결과.html`: 마지막 검증 완료 엑셀·대시보드 링크.
- 각 실행 폴더의 `refresh-plan.json`: 파일별 판정, 예정/실행 셀, 보류 목록.
- `value-changes.json`: Excel 저장값의 전후 변경.
- `verification.json`: 완료된 검사. 이 파일과 최근 결과 지정이 없는 중간 폴더는 검증 완료 결과가 아니다.
- `refresh-ledger.json`: 완료·실패 실행의 입력 및 결과 해시. 실패 기록은 완료로 간주하지 않는다.
- `dashboard-data.json`, `dashboard.html`: 같은 Excel 저장값에서 만든 로컬 검토 화면.

로컬 자료 계약은 `local-materials-1.1`로 확장했고 기존 1.0을 계속 읽는다. 새 `refresh` 필드는 갱신 근거만 담는다. 공식 업무 dataset·SQL 계약은 변경하지 않았으며 방법론·버전·신청·이력을 확정하거나 합치지 않는다. 기존 유형 보류는 자동 해제하지 않는다.

원본 업무 수식의 전면 검증·복구, 법정 기한 판정, 상시 동기화, ORS 로그인 수집, DB 연결, 외부 알림 발송, 공개 배포는 이 기능의 완료 범위가 아니다. 새 ORS 양식과 미검증 연결은 먼저 보류 상태로 점검한다.
