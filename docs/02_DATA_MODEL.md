# 02. 데이터 계약과 이력

계약 파일: `schemas/dataset.schema.json` / 교환 필드: `config/field_map.json`. 정의되지 않은 추가 필드 금지. null은 빈 값이며 0·빈 문자열로 치환하지 않음.

| 원장 | 단위 | 주요 기준 |
|---|---|---|
| methodologies | 고유 방법론 | 코드·명칭·공식분야 원문·분류 근거·산업 범위·최초등록일·등록사실 확인일 |
| versions | 방법론별 버전 | 버전 번호·신규/개정·등록일·유효시작일·출처 |
| applications | 신청 사건 | 신규/개정·접수일·담당자·관련 방법론(신규 미등록이면 null) |
| review_events | 검토 사건 | 발생일·기록일·당시 단계·행위·보완대기·다음조치·출처 |
| status_events | 적용상태 사건 | active/inactive/unknown·발생일·기록일·출처 |
| sources | 근거 | 공식/수동/합성 구분·공개/내부 구분·URL·파일해시·확인일 |

신규 신청은 아직 방법론 ID가 없을 수 있음. 개정 신청은 기존 방법론 ID 필요. 관계는 ID로 연결하며 명칭 문자열로 연결하지 않음. version은 방법론 내 유일, sequence는 이력 테이블 내 전역 유일 정수(1~99999). 같은 날 여러 사건은 sequence로 정렬.

스냅샷 포함: occurred_on<=as_of AND recorded_on<=knowledge_as_of. 날짜는 YYYY-MM-DD. 기록일을 사건일보다 앞당기지 않음. 정정은 원본 삭제 대신 증빙이 있는 신규 사건으로 추가. 동일날의 순서가 불분명하면 임의 순서를 공식 사실로 단정하지 말고 관리자 확인.

현재 단계는 마지막 적격 이력의 stage. 첫 이력은 transition이어야 함. stage가 바뀌면 transition 필요. supplement_requested/received는 동일 단계에서 대기 상태를 바꿈. 현재 단계 진입일은 마지막 실제 단계 변경일이며 단순 동일단계 메모는 초기화하지 않음.

적용가능 건수는 등록확인 방법론 중 마지막 적용상태 active인 건. 신규/개정의 법적 적용조건 자체를 판정하는 기능은 아님. 등록확인일만 존재하면 확인분 누적에 포함하지만 과거 최초등록연도는 추정하지 않음.

산업 분류·관장범위는 현재 원장의 주석과 증빙을 유지. v1의 scope는 단일 내부 집계범주, official_sector는 원문 보존 문자열. 다중 기술분류는 technology 태그 고도화로 확장할 수 있지만 분류 간 합산 중복에 주의. 완전한 과거 분류이력은 별도 snapshot 보관 필요.

파일은 원본→staging→검증→확정 JSON 순서로 처리. 잘못된 수집 결과를 곧바로 확정 원장으로 덮어쓰지 않음. 누락은 삭제·취소와 다름. 데이터 갱신은 파일 해시와 비교기준을 남긴 뒤 별도 승인.
