# 관리 Tool 연동·분류 조회

이 화면은 로컬 관리 원장의 행을 분류하는 조회 기능이다. 고유 신청 수나 공식 등록 통계로 승격하지 않는다. 방법론 신청, 사업 평가, 감축량 인증, 정보 비공개 신청을 각각 표시한다. ORS 복사 시트와 내부 관리 시트를 중복 합산하지 않는다.

## 엑셀에서 사용

기존 Tool을 보존한 새 버전의 첫 세 시트만 분석용으로 추가한다.

1. `DB_대시보드`: 업무구분·국내외·신청연도·원문상태·진행상태·담당자 슬라이서를 선택한다. Ctrl 또는 슬라이서의 다중 선택 버튼으로 여러 항목을 고른다.
2. `DB_연동원장`: 분야·신청유형·날짜확인·유형확인 보조 슬라이서와 표 머리글 필터를 쓴다. 신청월 등 다른 열도 필터할 수 있다. 모든 슬라이서는 같은 표를 제어하므로 다른 시트에 걸린 조건도 함께 적용된다.
3. `DB_분류집계`: 그래프에 생략된 전체 분류를 확인한다. 기존 주요 범주 밖의 값은 ‘새 분류(목록 외)’에 포함되며 누락하지 않는다.

슬라이서의 필터 해제 버튼으로 조건을 지운다. 표 머리글에 설정한 필터는 해당 열에서도 해제한다. 빈 예비 행은 명칭이 입력되기 전에는 집계하지 않는다. 공란 범주와 실제 미확보는 구분하며, 데이터가 없는 선택 결과의 0은 원장행 조회 결과다.

원본 수정은 기존 업무 시트에서 한다. 추가 시트는 원본 셀을 참조하며 원본 수식을 대신하지 않는다. Excel의 계산이 수동이면 계산을 실행해야 한다. 새 기록을 입력한 뒤에는 **데이터 → 다시 적용**으로 표 필터를 갱신한다. 각 시트별 추가 50행까지만 미리 연결하며 정확한 마지막 행은 대시보드 하단에 표시한다. 그 범위 밖의 추가, 시트 이름·열 구조 변경, 다른 Tool로 교체는 재매핑이 필요하다.

## 웹에서 사용

자료 탐색의 ‘분류 대시보드’에서 관리 자료를 먼저 고른다. 11가지 분류를 복수 선택할 수 있으며, 같은 분류 안은 OR, 서로 다른 분류 사이는 AND 조건이다. 검색어는 명칭·원본번호·담당자·시트에 적용한다. 그래프 막대를 누르면 해당 조건을 추가하거나 해제한다.

교차표의 행·열 분류를 바꿔 연도 × 상태, 담당자 × 진행상태, 분야 × 신청유형 등으로 조회한다. 원본 위치 버튼은 해당 시트의 정확한 행을 보여준다. ‘시트 전체 보기’로 주변 맥락을 확인한다.

웹은 로컬 JSON을 불러온 시점의 자료다. Excel 수정이 웹에 실시간 반영되지는 않으며 검토 JSON을 다시 생성·불러와야 한다. 공개 배포물에는 내부 JSON이나 원장이 포함되지 않는다.

## 계산과 해석

- `config/management_views.json`이 두 구현의 공통 열 매핑이다. Python과 웹은 같은 원본 행 ID와 분류 결과를 비교한다.
- Excel은 직접 셀 참조로 명칭이 있는 행을 연결하고, `SUBTOTAL(103, 행ID)`로 필터에 남은 행을 구한 뒤 `SUMIFS`로 분류한다. 원본시트·원본행·원본번호를 함께 보존한다.
- 공백 정리는 분석용 분류에만 적용하며 원본을 수정하지 않는다. 원본 오류는 ‘원본 오류’, 미입력은 ‘미확보’로 표시한다.
- 신청연도·월은 실제 신청일에서만 구한다. 월까지만 있는 날짜는 ‘월까지만 확인’으로 표시하며 일자를 확정하지 않는다. 부정확한 날짜를 임의의 연도에 넣지 않는다.
- 신규·개정 불일치로 이미 보류된 항목은 값이 바뀌어도 자동 확정하지 않는다. 담당자 확인이 필요하다. 미연결 신규 행은 ‘연결 미확정’으로 남긴다.
- 업무의 원문 상태·담당자 표기를 조회한다. 법정기한, 승인율, 표준 검토 단계, 공식 등록일을 추정하지 않는다.
- Excel 그래프는 최초 생성 시의 주요 범주와 기타를 표시한다. 필터 조건에 따라 상위 순위를 다시 정렬하는 웹 그래프와 표시 순서는 다를 수 있으나 동일 조건의 분류 합계는 같아야 한다.

## 구현 범위

로컬 조회·슬라이서·차트·셀 참조·분류 집계를 구현했다. DB, 공동편집, 자동 발송, 웹과 Excel의 실시간 동기화는 제공하지 않는다. 실제 실행 결과와 미검증 항목은 `verification/`의 이번 검증 기록을 따른다.
